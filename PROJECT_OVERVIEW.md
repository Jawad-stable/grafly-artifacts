## 1. What Grafly Is

**Grafly** is a gamified **design education** mobile app — a "Duolingo for visual
design" that teaches design principles through interactive lessons, an AI design
mentor that critiques real layouts, and a structured skill tree progression.

The app's core premise: **learn design by actually designing**, not just
watching. Users tap, drag, arrange, and choose between layouts in 13 different
question types, earn XP, build streaks, spend coins on cosmetics for the
mascot, and chat with an AI mentor (called **Grafly**) about real design work.

This repository is a **pnpm monorepo** containing five artifacts and four
shared libraries that together produce the production app, its backend, and
the marketing/presentation materials around it.

| Artifact | Kind | Purpose |
|---|---|---|
| `artifacts/grafly` | mobile (Expo) | The user-facing Grafly app (iOS/Android/web). |
| `artifacts/api-server` | api (Express 5) | Backend that proxies AI critique + TTS and serves design images. |
| `artifacts/intro-outro` | video (React + Vite) | A ~2-minute animated brand reel. |
| `artifacts/pitch` | slides (React + Vite) | The Grafly investor / hackathon pitch deck. |
| `artifacts/mockup-sandbox` | design (React + Vite) | A component preview server used to mock variants on the canvas. |

### Top-level configs you should know about

- **`.replit`** — Declares two language modules (`nodejs-24`, `python-3.11`),

  `20938`, `21477`, `23788` etc. mapped to external `80`, `3000`, `3001`,
  `8000`, `8008`, `5000`, `4200`, `5173`, etc.), the `[deployment]` block
  (`autoscale` target, prunes the pnpm store after build), the `[postMerge]`
  hook (`scripts/post-merge.sh`, 20 s timeout), `[agent]` set to expert mode
  on the `PNPM_WORKSPACE` stack, and the GitHub integration declaration. It
  also pins two **shared `[userenv]`** variables —
  `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` — so every
  workflow sees them.
- **`pnpm-workspace.yaml`** — Lists the workspace packages, declares a
  shared **dependency catalog** (`react` 19.1.0, `react-dom` 19.1.0,
  `framer-motion` ^12.23, `vite` ^7, `tailwindcss` ^4.1, `@tanstack/react-query`
  ^5.90, `drizzle-orm` ^0.45, `zod` ^3.25, `lucide-react` 0.545, `tsx` ^4.21,
  several `@replit/vite-plugin-*`), and a **massive override block** that
  excludes platform-specific binary subpackages (Android/Darwin/FreeBSD
  variants of esbuild, rollup, lightningcss, tailwindcss-oxide, ngrok,
  expo-ngrok-bin) to keep installs lean on Linux. It also pins security
  patches (`tar` ^7.5.13, `node-forge` ^1.4, `path-to-regexp` ^8.4,
  `lodash` ^4.18.1, `picomatch` ^4, `yaml` ^2.8, etc.) and sets
  `minimumReleaseAge: 1440` (24 h) so freshly-published packages can't
  sneak in.
- **`tsconfig.base.json`** — Strict TypeScript: `strictNullChecks`,
  `strictBindCallApply`, `noImplicitAny`, `noImplicitReturns`,
  `noFallthroughCasesInSwitch`, `useUnknownInCatchVariables`,
  `isolatedModules`, ES2022 target, `bundler` module resolution, the
  `workspace` custom condition.
- **`replit.md`** — The living source-of-truth doc. It captures the
  product overview AND a list of explicit **user preferences** that the
  agent is contractually required to respect:
  - All UI scale/slide animations use `withTiming` + `Easing.out(Easing.cubic)` —
    *never* `withSpring` (overshoot risk), except for the mascot's intentional
    bounciness.
  - **No hyphens / dashes in UI strings.**
  - Coins shown only on home / shop / lesson-results.
  - Hearts shown only on the lesson screen.
  - Streak shown only on the home screen.
  - Mascot is *only* rendered through the `GraflyMascot` component.
  - Default theme is **light**.
  - Editorial design aesthetic (magazine / collage feel).
  - All primary CTAs use `PressScale` for consistent press feedback.
  - Iterative development: ask before major changes.
- **`.gitignore`** — Standard Node + Expo + IDE excludes plus `attached_assets/`,
  `.env*`, `.cache/`, `.local/`, and stranded git pack temp files.
- **`.replitignore`** — Just excludes `.local` so deploy images stay small.

## 3. Tooling, Conventions & Workspace Setup

- **Package manager**: `pnpm@10.26.1` (enforced by a `preinstall` hook that
  refuses npm/yarn).
- **Top-level scripts**:
  - `pnpm build` — `pnpm run typecheck && pnpm -r --if-present run build`
    runs the libs typecheck, then every package's build.
  - `pnpm typecheck` — typechecks libs first (`tsc --build`), then every
    artifact and the scripts package.
- **Path mapping** — The mobile app uses `@/*` for absolute imports inside
  `artifacts/grafly/**` (configured per-package in its `tsconfig.json`).
  Other artifacts and libs use plain workspace package names
  (`@workspace/api-zod`, `@workspace/api-client-react`, etc.) via
  `workspace:*` deps.
- **Codegen flow** — `lib/api-spec` is the source of truth; `pnpm codegen`
  there runs Orval to regenerate Zod schemas in `lib/api-zod/src/generated/`
  and React Query hooks in `lib/api-client-react/src/generated/`.
- **Database migrations** — `pnpm --filter db push` runs `drizzle-kit push`
  against `DATABASE_URL`. This is what the post-merge hook calls.

### 4.3 Routing & Navigation

- **Root `_layout.tsx`** wraps the tree in providers (Auth → Game → Profile)
  and loads Teshrin + Nunito fonts. The **`AuthGate`** waits for
  `loading || !hydrated || !profileHydrated` before redirecting, so the
  splash never flashes the wrong route.
- **Tab bar (`(tabs)/_layout.tsx`)** is a custom **floating frosted-glass
  pill** with five icon-only tabs. Width is computed dynamically via
  `getBottomBarWidth` in `constants/layout.ts`.
- **Stack transitions**: `slide_from_right` is the default; tabs and
  onboarding fade; modals (paywall, lesson exit) `slide_from_bottom`.
- `initialRouteName` is `(tabs)`.

### 4.4 State Management

Three React Contexts, layered top to bottom in `_layout.tsx`:

```tsx
<AuthProvider>
  <GameProvider>
    <ProfileProvider>
      <RootLayoutNav />
    </ProfileProvider>
  </GameProvider>
</AuthProvider>
```

#### `context/AuthContext.tsx`
- Wraps `@supabase/supabase-js`.
- Exposes `session`, `user`, `loading`, plus `signInWithGoogle`,
  `signInWithEmail`, `signUpWithEmail`, `signOut`.
- Handles deep-link OAuth callbacks via `expo-linking` + `expo-web-browser`,
  finalising sessions in `app/auth-callback.tsx`.

#### `context/GameContext.tsx` (the heart of the app)
- A `useReducer` over `GameState`: `xp`, `level`, `coins`, `hearts`,
  `maxHearts`, `streak`, `lastActiveDate`, `streakShields`,
  `xpBoosterUntil`, `isPro`, `completedLessons`, `currentCourse`,
  `currentNode`, `weeklyXP`, `onboardingComplete`, `placementLevel`, etc.
- Persists to **AsyncStorage key `@grafly_v1_state`** and **debounce-syncs
  to Supabase `game_state`** ~1.5 s after every change when signed in.
- Exposes high-level actions: `addXP`, `loseHeart`, `refillHearts`,
  `incrementStreak`, `useShield`, `activateBooster`, `purchase`,
  `markLessonComplete(courseId, nodeId, lessonId)`,
  `completeOnboarding(placementLevel)` (signature simplified after the
  recent split — see §4.10), `setPro`, etc.
- `getLevelFromXP(xp)` formula: `100 * 1.3 ^ level` — superlinear so each
  level needs roughly 30 % more XP than the last.
- A **hydration flag** prevents writes from clobbering disk state before
  AsyncStorage finishes restoring.

#### `context/ProfileContext.tsx` (added in the latest session)
- Owns the *preferences / identity* slice that used to live in GameContext:
  `username`, `handle`, `profilePic`, `voiceEnabled`, `themeMode`
  (`"light" | "dark"`), `proBannerDismissed`.
- Actions: `UPDATE_PROFILE`, `TOGGLE_VOICE`, `SET_THEME`,
  `DISMISS_PRO_BANNER`, `RESTORE`.
- Persists to **AsyncStorage key `grafly_profile`**.
- Mirrors `voiceEnabled` into `voiceService.setVoiceEnabled(...)`,
  **gated on its own `hydrated` flag** so the default `true` cannot
  transiently overwrite a persisted `false`.
- Helpers: `updateProfile`, `toggleVoice`, `setTheme`.
- See `EDITS.md` for the full split summary.

### 4.6 Constants (`constants/`)

- **`colors.ts`** — Light + dark color tokens. Dark-mode `success` is
  `#22DD88`; light-mode `success` was recently aligned to `#12B870`
  (was `#138354`) for closer perceived brightness while preserving
  ~4.6:1 contrast on white. Brand cyan `#00A4FA`, navy `#21263F`.
- **`contrast.ts`** — Utility helpers (e.g. `onBrand(bg)`) that pick a
  WCAG 2.1 AA–compliant text color for any background, including the
  gradient adjustments used on colored hero surfaces.
- **`fonts.ts`** — Teshrin font family registration (Regular / Medium /
  Bold), plus the secondary Nunito family used for stat numerics.
- **`layout.ts`** — Layout constants: `getBottomBarWidth`,
  horizontal padding (`24` px), card radii, etc.
- **`assets.ts`** — Centralised `require(...)` paths so callers don't
  duplicate paths to mascot / logo PNGs.
- **`lessons.ts`** — Massive `COURSES` data: the **Design Principles**
  course with **6 modules × 3–5 lessons each**, and the lesson DSL.
  Each lesson has optional `intro` cards + a `ModuleCompleteCelebration`
  banner at the end.

### 4.7 Hooks & Utils

- **`hooks/useColors.ts`** — Reads `themeMode` from `useProfile()` and
  returns the active palette + helpers. Single source of truth for
  color reads; components never import the raw `colors.ts` tokens
  directly.
- **`utils/adaptive.ts`** — Scaling utilities for adapting type sizes
  and spacing across small/large phones.

### 4.8 Services (`services/`)

- **`supabase.ts`** — Singleton `createClient(...)` configured with the
  shared `EXPO_PUBLIC_SUPABASE_URL` / `EXPO_PUBLIC_SUPABASE_ANON_KEY`
  env vars (set in `.replit`). Auth persistence uses AsyncStorage.
- **`aiCritique.ts`** — Thin client that POSTs to
  `/api/critique/chat` on the API server. Sends
  `{ designTitle, designDescription, designImageUrl, messages }` and
  returns `{ reply }`. Also fetches the public design list from
  `/api/critique/designs` and `/api/critique/designs/random`.
- **`voiceService.ts`** — `expo-av` based audio + TTS playback layer.
  Reads `@grafly_voice_enabled` flag from AsyncStorage. Calls the
  `/api/tts` proxy and plays the returned base64 MP3.

### 4.9 Gamification Model (full spec)

| Concept | Rules |
|---|---|
| **XP** | Awarded per correct answer + lesson completion. `level = floor(log_{1.3}(xp/100))`. |
| **Coins** | Awarded for finishing lessons, daily streaks, and one-off achievements. Spent in shop on shields, hearts, boosters. |
| **Hearts** | 5 max. One lost per wrong answer. Refill via shop, time-based regen, or unlimited if `isPro`. The lesson screen redirects to `paywall` when hearts hit 0. |
| **Streak** | Days with at least one lesson completed. Resets at midnight unless a `streakShield` is consumed. |
| **Streak Shields** | Inventory item; auto-spent to protect a streak from a single missed day. |
| **XP Booster** | Time-windowed 2× XP multiplier (24 h). Tracked via `xpBoosterUntil` timestamp. |
| **isPro** | Boolean Pro entitlement → unlimited hearts and unlimited daily critique. |
| **Achievements** | Triggered for milestones: first critique sent, first perfect lesson, etc. |

### 4.10 Lesson Engine (`app/lesson.tsx` + `LessonScenes.tsx`)

13 question types are supported via a discriminated-union DSL in
`constants/lessons.ts`:

1. `multiple_choice`
2. `true_false`
3. `image_id` — identify a labeled element in an image
4. `spot_the_difference`
5. `tap_the_element`
6. `arrange_in_order`
7. `drag_to_match`
8. `fill_in_blank`
9. `spot_bad_design`
10. `choose_better_design`
11. `drag_drop_layout`
12. `five_second_test` — first-impression recall test
13. `find_the_cta`

Lessons may begin with one or more `intro` cards (text + visual) and
end with a `ModuleCompleteCelebration` banner if the lesson closes a
module. The screen also installs a **lesson exit guard**
(`confirmExit` callback) that intercepts close/back presses to warn
about losing mid-lesson progress; out-of-hearts redirects send the
user to `paywall.tsx`.

### 4.11 Onboarding (`app/onboarding.tsx`)

A 7-step editorial flow with a clearly labeled "Skip for now" exit:

```ts
const STEP_ORDER: Step[] = [
  "welcome", "name", "goal", "level", "time", "placement", "results", "signup",
];
```

Internal `nextStep()` / `prevStep()` helpers clamp `setStep((cur) => …)`
within `STEP_ORDER` bounds — every forward CTA calls `nextStep()`
(no hard-coded targets), and back buttons call `prevStep()`.

A single helper unifies the four "finish" callsites
(`finishWithoutAccount`, `finishWithGoogle`, sign-in/sign-up success
paths in `finishWithEmail`):

```ts
function finishOnboarding() {
  updateProfile({ username: displayName, handle: "", profilePic: "" });
  completeOnboarding(placementResult);
}
```

`completeOnboarding(placementLevel)` no longer carries identity fields —
those live in `ProfileContext` now.

### 4.12 AI Critique Screen (`app/(tabs)/critique.tsx`)

- Chat-style UI with a **redesigned hero**, composer, and warm
  "friend who happens to be a senior designer" mentor voice (driven by
  the server-side `SYSTEM_PROMPT` — see §5).
- Visual identity: **brand-squiggle backdrop**, tinted pills for
  eyebrows, distinct user/assistant bubble styling for AA contrast.
- The mentor avatar is the **AiBot star** (a spinning-fan animation
  during `thinking`) — *not* the octopus mascot. The two are deliberately
  separate identities.
- A `TypewriterText` component animates assistant replies one
  character at a time.
- A first-run `CritiqueOnboarding` modal explains the loop.
- Opener prompts are randomized from `OPENER_TEMPLATES` so the chat
  never feels generic.

### 4.13 Theming, Typography, and Animation Conventions

- **Default theme is light.** Dark mode is fully supported and toggled
  via the welcome screen + the profile screen.
- **Typography**: Teshrin custom font (Regular / Medium / Bold) for
  body and headlines, Nunito for stat numerics. All text wraps in
  `AText` so swapping families is one place.
- **Animation rule (hard preference)**: every UI scale/slide animation
  uses `withTiming` + `Easing.out(Easing.cubic)`. **No `withSpring`**
  outside the mascot — overshoot is forbidden in product UI.
- **Editorial design**: magazine-like hero headers, near-black pill
  primary CTAs, `24` px horizontal padding, occasional collage motifs
  via `BrandSquiggle`.

### 4.14 Persistence Summary

| Storage | Key | Owner | Contents |
|---|---|---|---|
| AsyncStorage | `@grafly_v1_state` | GameContext | XP, coins, hearts, streak, etc. |
| AsyncStorage | `grafly_profile` | ProfileContext | username, handle, profilePic, voiceEnabled, themeMode, proBannerDismissed |
| AsyncStorage | `@grafly_voice_enabled` | voiceService (mirror) | Boolean read by `voiceService` (mirrored from ProfileContext after hydration) |
| Supabase table | `game_state` | GameContext | Cloud-sync of game state, debounced 1.5 s |
| Supabase table | `critique_designs` | API server | Catalog of critique designs |

### 4.15 Auth flow (signed-in path)

1. User taps **Continue with Google** in `auth.tsx` (or onboarding signup step).
2. `AuthContext.signInWithGoogle()` opens the OAuth URL via
   `expo-web-browser.openAuthSessionAsync(...)` with the redirect
   URI built from `expo-linking` + the `grafly://` scheme.
3. The OAuth provider redirects to `grafly://auth-callback?...`,
   which `app/auth-callback.tsx` parses and finalises with
   `supabase.auth.setSession(...)`.
4. `AuthGate` re-renders, sees `session` set, and routes to `(tabs)`.

### 5.3 Middleware

- **CORS** — `cors()` allowing all origins (the mobile client runs from
  arbitrary Replit dev domains).
- **Logging** — `pino-http` redacts `Authorization` and `Cookie` headers.
- **Body parsing** — `express.json({ limit: "1mb" })` and
  `express.urlencoded({ extended: true })`.
- **Static** — `express.static("assets/designs")` mounted at
  `/api/critique/design-images` so NVIDIA NIM can fetch image URLs for
  multimodal vision.

|---|---|---|---|---|
| `GET /healthz` | Liveness probe | — | `{ status: "ok" }` validated against `HealthCheckResponse` from `@workspace/api-zod` | none |
| `GET /api/critique/designs` | List active critique designs | — | `[{ id, title, description, image_url, difficulty }]` | Supabase `critique_designs` (with hardcoded `FALLBACK_DESIGNS` if DB unreachable) |

| `POST /api/critique/chat` | Multimodal AI chat with the mentor | `{ designTitle, designDescription, designImageUrl, messages }` | `{ reply: string }` | NVIDIA NIM (`meta/llama-4-maverick-17b-128e-instruct`) — image attached to the *final* user message |

### 5.5 The Mentor Voice (`SYSTEM_PROMPT` in `routes/critique.ts`)

The prompt instantiates **Grafly** as a "warm, patient design mentor":

- "A friend who happens to be a senior designer: curious, grounded,
  never preachy."
- **Never** call the design "your work" — the student didn't make it.
- **Never** claim to edit the static image.
- 80 % Socratic questions, 20 % answers; replies stay 4–8 lines.
- **Strict language detection** — replies in the user's language
  (Arabic, Spanish, French, etc.).

## 9. Shared Libraries (`lib/*`)

All four packages are pure TypeScript, consumed by artifacts via
`workspace:*` dependencies.

### 9.1 `lib/api-spec` — API source of truth

- `openapi.yaml` — OpenAPI **3.1.0** spec. Currently defines the
  `/healthz` endpoint and the `HealthStatus` schema; the AI/TTS
  routes are not yet captured here.
- `orval.config.ts` — Orval config with two outputs:
  1. React Query hooks → `lib/api-client-react/src/generated/`
  2. Zod schemas → `lib/api-zod/src/generated/`
- `package.json` exposes `pnpm codegen` → `orval --config ./orval.config.ts`.

### 9.2 `lib/api-zod` — Generated Zod schemas

- `src/generated/api.ts` — `HealthCheckResponse` and friends.
- `src/index.ts` — Public re-exports (schemas + inferred types).
- Consumed by `artifacts/api-server/src/routes/health.ts` for response
  validation before send.

### 9.3 `lib/api-client-react` — React Query hooks for the client

- `src/generated/api.ts` — `useHealthCheck` and per-operation hooks.
- `src/generated/api.schemas.ts` — TS types matching the OpenAPI shapes.
- `src/custom-fetch.ts` — A wrapper over `fetch` that:
  - Lets callers set the base URL via `setBaseUrl(url)`.
  - Lets callers inject a bearer token via `setAuthTokenGetter(fn)`.
  - Wraps errors in typed `ApiError` and `ResponseParseError` classes.
- Designed to be the single client surface for any artifact that talks
  to the API server (currently the mobile app uses ad-hoc `fetch` for
  critique/TTS pending OpenAPI expansion of those routes).

### 9.4 `lib/db` — Drizzle ORM data layer

- `src/schema/index.ts` — Central re-export. Each table is intended to
  live in its own file under `src/schema/`.
- `drizzle.config.ts` — Drizzle Kit config, dialect `postgresql`.
- Scripts:
  - `pnpm push` → `drizzle-kit push` (direct schema sync) — invoked by
    the post-merge hook so DB schema follows merged code automatically.
- Uses `drizzle-zod` for Zod inference from tables, and `pg` as the
  driver. Requires `DATABASE_URL`.

## 12. Security & Threat Model

`threat_model.md` is the canonical document; here are the highlights.

- **Production attack surface**: only `artifacts/api-server` and
  `artifacts/grafly`. The pitch deck, intro/outro reel, and mockup
  sandbox are dev-only and explicitly de-scoped.
- **Trust boundaries**: mobile client → API server (server holds
  privileged third-party keys), mobile client → Supabase (anon key
  only — relies on RLS), API server → third parties (NVIDIA, ElevenLabs).
- **Highest-risk files** (per `## Scan Anchors`):
  - `artifacts/api-server/src/routes/critique.ts`
  - `artifacts/api-server/src/routes/tts.ts`
  - `artifacts/grafly/context/AuthContext.tsx`
  - `artifacts/grafly/app/auth-callback.tsx`
  - `artifacts/grafly/context/GameContext.tsx`
  - `artifacts/grafly/app/paywall.tsx` and `app/(tabs)/critique.tsx`
- **STRIDE**:
  - *Spoofing* — Auth callbacks must be tied to an in-app transaction,
    never trust arbitrary deep links carrying session material.
  - *Tampering* — All gameplay/entitlement state on the client is
    untrusted; entitlements, usage caps, and cross-user data must be
    verified server-side.
  - *Information disclosure* — Supabase RLS is the primary control;
    logs already redact `Authorization`/`Cookie`.
  - *DoS* — Both critique and TTS are paid pass-throughs and need
    abuse controls (auth/quota/rate limits).
  - *Elevation* — No Pro/free or signed-in/anon boundary may be
    bypassable by toggling client state.

## 14. Glossary of Conventions & Style Rules

These come from `replit.md`'s **User Preferences** section and are treated
as hard rules across the codebase:

1. **Animations**: `withTiming` + `Easing.out(Easing.cubic)` only.
   *Never* `withSpring` (the mascot is the lone exception — its bounce
   is intentional).
2. **No hyphens or dashes in UI strings.** Copy uses commas, periods,
   or em-spaces instead.
3. **Stat visibility**:
   - Coins → home, shop, lesson results only.
   - Hearts → lesson screen only.
   - Streak → home screen only.
4. **Mascot** is rendered exclusively via `<GraflyMascot />`.
5. **Default theme is light** (`themeMode: "light"` initial in
   `ProfileContext`).
6. **Editorial design aesthetic** — magazine/collage feel, near-black
   pill primary CTAs, 24 px horizontal padding, brand-squiggle motifs.
7. **Press feedback** — every primary CTA wraps in `PressScale`.
8. **Iterative development** — propose major changes before doing them.
9. The **AiBot** mentor avatar (Critique screen) is *not* the octopus
   mascot; they're deliberately distinct identities.
10. All text goes through `<AText />`; raw `<Text>` is forbidden.
